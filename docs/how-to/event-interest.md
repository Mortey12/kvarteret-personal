# Enable the event click counter

The sibling `samfunnetibergen` website calls the signed routes in `app/api/v1/event_interest.py` to record each accepted click on an event heart. `app/domain/event_interest/repository.py` persists retry-safe batches in the existing PostgreSQL database. Event content and visibility remain in Sanity and are validated by the website; this does not restore `/api/v1/events`.

Apply migrations `20261001_1400` and `20261001_1500`. The second adds `public.event_interest_clicks` with event ID, UUID batch ID, source digest, click quantity and expiry, preserving all previously stored taps and their expiry. It enables RLS without public policies and revokes PUBLIC access. The old response table remains for rollback compatibility; new writes use only the click-batch table. Downgrading the second migration removes new click history, so retain a backup if rollback is required.

Both services use the shared server-only `PERSONAL_SIGNING_SECRET` (at least 32 characters), the same key that signs volunteer prospects and booking requests; the `event-interest-v1` prefix keeps these signatures distinct. `EVENT_INTEREST_SECRET` was retired on 2026-10-13; Personal accepts only the shared key and its optional rotation key. The website uses `PERSONAL_APP_BASE_URL` for this backend. Deploy the migration and backend before website PR #162. The revised contract replaces the unmerged weighted-response version; coordinate both updated PRs.

POST `/api/v1/event-interest/read` accepts `{event_id, source_hash}`, with nullable source digest. POST `/api/v1/event-interest/response` requires `{event_id, source_hash, clicks, batch_id}`, where `clicks` is an integer 1–1000 and `batch_id` is a UUID v4 string. Both return `{taps, count}` and forbid caching. `taps` is the current source's retained clicks and `count` is all retained event clicks. Each event-specific browser source can contribute twelve clicks before its heart is full. Counts are raw clicks, with no weighted score or zero-count deletion operation.

An event-level transaction lock serializes inserts and aggregation and atomically clamps accepted clicks to the source’s remaining allowance. The unique `(event_id, batch_id)` key makes an identical transport retry a no-op. Separate batches count until the shared source reaches twelve, even when concurrent tabs share the same cookie. Further writes return the current count without adding clicks. The website retains the in-flight batch ID across failures, queues later clicks, and initializes its signed event cookie before writing. It shows only the heart and an integer count in normal operation, with retry when saving fails. The heart fills at twelve accepted taps, emits confetti, and disables further clicks.

All requests require `X-Kvarteret-Timestamp`, `X-Kvarteret-Nonce` (a UUID), and `X-Kvarteret-Signature` (`v1=<hex>`). The HMAC-SHA256 canonical value is `event-interest-v1`, timestamp, nonce, HTTP method, request path and SHA256 digest of the exact body, joined with newlines. Timestamp tolerance is five minutes. Authentication nonces cannot repeat within ten minutes; transport retries use a new nonce but retain the click-batch ID. A global 3000-request-per-minute limit protects the service without storing IP addresses.

Schedule `uv run python -m scripts.cleanup_event_interest` daily. Each new batch expires 90 days after creation; reads ignore expired rows and writes prune expired batches for that event. Cleanup also removes expired legacy rows. The count is retained clicks, not people or attendance. Source cookies restore personal heart fill and share the twelve-click allowance across tabs. Another browser or cleared cookie creates a separate source. No accounts, IP addresses or fingerprints are stored, and the UI has no undo or information control. See the sibling website's `docs/how-to/event-interest.md` for its source-cookie contract and browser behavior.

Run `uv run pytest tests/api/event_interest`. Set `EVENT_INTEREST_TEST_DATABASE_URL` to a disposable `postgresql+asyncpg` URL to include concurrent writes, same-batch retries, same-source independent batches, event isolation and expiry tests. Regenerate OpenAPI with `uv run python -m scripts.export_openapi`, then verify with `--check` (this checkout has no Makefile).
